# Scripture-Grounding: Shadow → Enforce 승격 계약 (설계 노트)

> **작성**: 2026-07-22. 현행 Shadow Gate(2026-07-19 설계·구현)는 판정만 기록하고 사용자 노출을 바꾸지 않는다. 본 문서는 **shadow 를 enforce 로 승격할 때의 계약(contract)** 을 미리 고정한다 — 승격 시점에 톤이 무뎌지는 것을 막기 위한 사전 결정.
> **사상적 근거**: rlm-forge TraceGuard 의 "부모의 주장은 자식의 증거로 뒷받침돼야 하며, 위반은 하드 실패" 계약과 동일 구조. xr 버전: **"묵상의 문장은 공급된 성경 본문에 근거해야 하며, 위반은 재생성이지 경고가 아니다."**

---

## 1. 계약 (불변)

1. **판정은 결정론적이다.** 문장 분리 → 임베딩 → 문장별 max cosine → 정책 집계(GroundingPolicy)의 파이프라인은 같은 입력에 같은 verdict 를 낸다. LLM 재판정으로 verdict 를 뒤집을 수 없다.
2. **REJECTED = 하드 실패.** enforce 모드에서 verdict 가 reject 면 그 생성물은 사용자에게 **절대 나가지 않는다**. soft 경고·"주의 표시 후 노출"·운영자 재량 통과는 계약 위반이다. 게이트가 장식이 되는 경로를 설계 단계에서 봉쇄한다.
3. **실패 시 행동은 재생성, 그 다음은 정적 대체.** reject → 원본 LLM 재생성 1회(CONTENT-WORKFLOW §3 revise 규칙과 동일 상한) → 재차 reject 면 **정적 큐레이션 콘텐츠로 대체**(faith_tone×lament 사전 큐레이션 — R5 opt-out 경로와 동일 자산 재사용). 사용자는 빈 화면이 아니라 항상 *검증된* 콘텐츠를 받는다.
4. **증거 핸들이 판정과 함께 보존된다.** 문장별 (sentence, max_cosine, matched_passage_ref) 를 Micrometer 지표 + 감사 로그로 남긴다. "왜 통과/차단됐나"를 사후 재구성할 수 있어야 한다.
5. **R1~R5 는 이 게이트보다 상위다.** grounding PASS 는 신학·안전 통과를 의미하지 않는다 (근거성≠정통성≠안전성). 기존 안전 게이트를 대체하지 않고 그 아래층에 추가된다.

## 2. 승격 조건 (전부 충족 시에만 enforce 전환)

| # | 조건 | 근거 지표 (shadow 기간 수집) |
|---|---|---|
| P1 | 구현 계획(2026-07-19 plan)의 전 Task 완료 + 테스트 green | gradle test 전체 |
| P2 | shadow 2주 이상 운영, verdict 표본 확보 | grounding 지표 카운터 |
| P3 | **오탐(false reject) 률 측정** — reject 표본을 사람이 검수해 "실제로는 근거 있는 문장" 비율 < 5% | reject 로그 수동 검수 |
| P4 | 임계값 확정 — maxUnsupportedRate(현행 튜닝 0.3)·cosine 컷을 shadow 분포 기반으로 고정하고 근거 문서화 | 분포 히스토그램 |
| P5 | 재생성→정적 대체 fallback 경로 구현 + 부하 검증 (재생성 폭주로 지연·비용 급증 없어야) | p95 지연·재생성률 |
| P6 | 운영자 대시보드에 reject 률 알람 (급등 = 모델/임베딩 드리프트 신호) | Micrometer → 기존 모니터링 |

## 3. 단계적 롤아웃

1. **enforce-canary**: 트랙 A 묵상 1종(예: Theme 1 일기묵상)만 enforce, 나머지 shadow 유지.
2. **enforce-partial**: R1 민감 콘텐츠 *제외* 전체 enforce. (민감 콘텐츠는 정적 큐레이션 비중이 높아 게이트 통과량 자체가 적음 — 마지막에.)
3. **enforce-full**: 전 LLM 생성 경로 enforce. shadow 모드 코드는 유지(플래그 복귀 가능해야 — 원클릭 롤백).

각 단계 전환 사이 최소 1주, P6 알람 무발화가 전환 조건.

## 4. 명시적 비목표 (non-goals)

- 성경 *해석의 정통성* 판정 — 임베딩 유사도는 근거성(grounding)만 본다. 정통성은 2단 의미 검증(신학 에이전트)과 CONTENT-WORKFLOW §3 의 몫.
- 사용자 입력(일기·기도문) 검열 — 게이트 대상은 **AI 생성물**뿐이다.
- 실시간 재임베딩 최적화 — 승격 계약과 무관한 성능 작업은 별도 계획으로.

## 5. 미결정 (승격 전 결정 필요)

- 재생성 시 프롬프트에 reject 사유(미근거 문장 목록)를 피드백할지 — 품질↑ vs 프롬프트 복잡도·비용↑
- 정적 대체 발동을 사용자에게 고지할지("AI 생성 대신 준비된 묵상입니다") — 투명성 vs UX 잡음. ETHICS-LEGAL.md 톤과 정합 필요.
- canary 대상 Theme 의 최종 선택 — 트래픽·민감도 데이터 보고 결정.
