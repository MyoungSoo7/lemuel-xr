# `scripture_ref` 참조 규약

성경 참조를 적는 두 가지 규약을 담는다.

1. **기계가 읽는 키** — 시나리오(`backend/src/main/resources/scenarios/*.yml`)가 적는
   `scripture_ref` 와 `scripture_passages` 테이블의 `reference` 열을 맞추는 규약
   (§규약 1~4). 2026-08-20 제정. 기계 검사는 `scripts/scripture_ref_check.py`
   (CI 러너 `scripture-ref:all`).
2. **사람이 읽는 표기** — 화면 자막·라벨·해설문에 괄호로 다는 한글 참조
   (§화면 표기 규약 5~7). 2026-08-22 추가. 기계 검사는
   `scripts/check_monologue_quotes.py` 의 E·F 축.

둘은 서로 다른 문자열이고 변환 관계가 아니다 — `ex-3:12` 와 `(출 3:12)` 는 같은 절을
가리키지만 한쪽에서 다른 쪽을 생성하지 않는다.

## 왜 규약이 필요했나

규약이 없던 동안 시나리오 8편이 서로 다른 문법으로 참조를 적었다.

| 적힌 것                | 어디        | 조회 결과                  |
| ---------------------- | ----------- | -------------------------- |
| `job-42:5`             | `job.yml`   | 열림                       |
| `ps-23:1-6`            | `david.yml` | 안 열림 — 범위 문자열      |
| `ruth-1:8,1:9,1:16`    | `ruth.yml`  | 안 열림 — 쉼표 묶음        |
| `ruth-1:19,1:20,1:21a` | `ruth.yml`  | 안 열림 — 반절 접미사 `a`  |
| `mt-5:3`               | `jesus.yml` | 안 열림 — 책 약어가 `matt` |

`reference` 열은 단일 절 키(`book_code-chapter:verse`) 하나만 안다.
`findFirstByReferenceAndTranslation` 은 정확 일치 조회다 —
범위·묶음·접미사는 파싱되지 않고 그냥 **안 맞는다**.

2026-08-20 실측으로 참조 44개 중 31개가 이 이유로 열리지 않았다.

## 규약

**1. `scripture_ref` 는 언제나 단일 절 키다.**

```
<book_code>-<chapter>:<verse>
```

정규식: `^[a-z0-9]+-\d+:\d+$`. 범위(`-6`)·쉼표 묶음(`,1:9`)·반절 접미사(`21a`) 금지.

**2. 절이 더 필요하면 `extras.additional_refs` 에 단일 절 키의 배열로 적는다.**

```yaml
scripture_ref: ruth-1:8
extras:
  additional_refs: ["ruth-1:9", "ruth-1:16"]
```

**3. `book_code` 는 시드가 이미 쓰는 약어를 따른다.**

정본 목록의 근거는 `V6__scripture_embeddings.sql:11` 주석
(`'gen' | 'ex' | '1sam' | 'ps' | 'matt'`) 과 실제 시드 행이다.
같은 책이 두 약어로 살면 안 된다 — `mt` 와 `matt` 가 그랬다.

**4. 한 절이 여러 절과 합쳐 번역된 경우, 키는 시작 절이고 `verse_end` 가 범위를 담는다.**

현대인의 성경은 삼상 17:38-39 · 창 41:34-35 · 룻 4:18-22 를 한 덩어리로 번역한다.
이때 행은 하나(`1sam-17:38`, `verse_end=39`)이고, 시나리오도 그 시작 절 키를 적는다.
39절을 따로 참조할 방법은 없다 — 번역본에 그런 단위가 없기 때문이다.

## 화면 표기 규약 (2026-08-22 추가)

위 규약은 **기계가 읽는 키**(`scripture_ref`)의 문법이다. 여기부터는 **사람이 화면에서
읽는 표기** — 자막·라벨·해설문 끝에 괄호로 다는 한글 참조 — 의 규약이다. 둘은 다른
문자열이고 서로 변환되지 않는다.

기계 검사: `scripts/check_monologue_quotes.py` (E·F 축).

**5. 책 이름은 약칭으로 적는다.**

```
(창 12:1)      (왕상 19:12)      (삼상 17:45)
(창세기 12:1)  (열왕기상 19:12)  ← 안 된다
```

근거는 취향이 아니라 이미 있는 다수다. TS 모놀로그의 `q()` 표기 44건이 전부 약칭이고,
정본 표 `docs/verses-monologues-gae.txt` 의 키도 약칭이며(`시 23:1<TAB>…`), 잠금 파일도
그 키를 쓴다. `content/**/*.yml` 만 전체 이름을 섞어 쓰고 있었다 — 2026-08-22 에
162건을 약칭으로 통일했다. F 축이 되돌아오는 것을 막는다.

**6. 인용이 아닌 문장은 참조 뒤에 한정어를 붙인다.**

```yaml
text_ko: "네가 가서 저 블레셋 사람과 싸울 수 없으리니 (삼상 17:33)"       # 인용 — 자구를 잰다
strong:  "두려움은 너의 적이 아니라 너의 동행자다. (삼상 17:45 참조)"      # 해설 — 안 잰다
```

한정어는 `참조 · 정서 · 배경 · 맥락 · 요약` 다섯이다. 붙으면 E 축이 그 문자열을 성경
자구로 재지 않는다. 해설문을 자구로 재면 **고칠 수 없는 실패** 가 나기 때문이다 —
저자가 성경이라고 주장한 적이 없는 문장이다.

이것은 게이트를 조용히 끄는 스위치가 아니다. 한정어는 화면에 그대로 떠서 사용자가
"인용이 아니라 근거"임을 읽고, 게이트 요약줄이 그 건수를 항상 같이 낸다
(`참조 표기 11건`). 그래도 남용은 가능하다 — 틀린 자막에 "참조" 를 붙이면 빨강이
사라진다. 기계가 막는 것은 여기까지고, 그 다음은 리뷰가 그 건수를 보는 것이다.

**7. 참조는 그것이 가리키는 인용 바로 뒤에 붙인다.**

```yaml
strong: "…부르신다. *내가 반드시 너와 함께 있으리라* (출 3:12) — 부름은 자격을 묻지 않는다."
strong: "…부르신다. *내가 반드시 너와 함께 있으리라* — 부름은 … (출 3:12)"   # 안 된다
```

추출기는 따옴표(또는 별표)와 참조가 **붙어 있는** 것만 인용으로 본다. 사이에 산문이
끼면 그 인용은 어느 축에도 안 잡힌다 — 실패가 아니라 **침묵** 이라 눈치채기 어렵다.
따옴표는 큰따옴표·홑따옴표·낫표 어느 쪽이든 된다.

## 이 규약이 보장하지 않는 것

키가 맞는다는 것은 **행이 있다** 는 뜻이지 **자구가 맞다** 는 뜻이 아니다.
본문 자구는 별도 검사(`scripts/scripture_text_check.py`) 가 잰다. 그리고 지금
미션 화면(`frontend/src/app/<char>/page.tsx`)은 `scriptureRef` 를 렌더하지
않는다 — `ScenePayloadAssembler:51` 이 문자열을 조인 없이 그대로 실어 보낼 뿐이다.
초록은 "열 수 있다" 이지 "열린다" 가 아니다.
