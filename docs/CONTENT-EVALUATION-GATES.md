# 콘텐츠 3단 평가 게이트 (Content Evaluation Gates)

> **작성**: 2026-07-22. 엘리야(Track B Theme 12) 파이프라인 실증 + "3축 하네스 스택"의 evaluate 패턴(기계→의미→합의)을 xr 콘텐츠에 명문화.
> **위치**: CONTENT-WORKFLOW.md 의 보완 문서 — 워크플로우(§2 상태머신·§3 AI 1차 검토)는 *언제/누가* 를, 본 문서는 *어떤 층위로 무엇을* 검증하는지를 정의한다.
> **원칙**: 층이 다르면 중복이 아니라 **보강**이다. 아래 3단은 서로를 대체하지 않는다.

---

## 0. 왜 3단인가

- 단일 게이트는 각자 고유한 실패 모드가 있다: 기계 lint 는 문맥을 모르고, LLM 검토는 "그럴듯함"에 속고, 사람은 규모에 진다.
- 엘리야 실증(2026-07-21): 기계 lint 가 있는 상태에서도 **의미 검토가 blocker 4건을 추가 적발**(crisis 번호 불일치·학대맥락 disclaimer 부재·R3 상태게이트 미배선·R5 프레이밍). 층이 달라서 잡힌 것들이다.
- 재작업 위치 전이: 잘못된 가정은 공개 후가 아니라 **제작 단계에서** 잡을수록 수정 비용이 자릿수로 준다.

## 1. 3단 구조

| 단 | 이름 | 검증 주체 | 무엇을 잡나 | 실패 시 |
|---|---|---|---|---|
| **1단** | 기계 검증 (deterministic) | lint·스크립트 (LLM 아님) | 형식·금칙어·불변식 | **하드 실패** — 빌드/머지 차단 |
| **2단** | 의미 검증 (semantic) | 전문 검토 에이전트 | 신학 정통성·안전선 실질 준수 | 판정 (approve / changes / block) |
| **3단** | 합의 검증 (consensus) | 다중 독립 검토 + 사람 | 단일 검토자의 편향·놓침 | 다수결·사인오프 |

### 1단 — 기계 검증 (전 콘텐츠 필수)

LLM 판단이 개입하지 않는, 위반이 스스로 드러나는 검사. Scene yml 에 이미 선언된 것들:

- `lint_forbidden_tokens` — R2/R3 금칙어 ("믿음이 부족", "빨리 회복" 등) 텍스트 매칭
- **crisis 자원 하드코딩 0건** — `{{crisis_resources.default}}` 토큰만 허용 (grep 검사)
- **R1 불변식** — 민감 Scene `branches: []` 유지, `R1_voice_self_harm_listener` 전 Scene 존재
- YAML 파싱 유효성 · 필수 필드(consent_card, footer, disputed_points) 존재
- "AI 보조 — 본문은 성경 참조" footer 존재

실행: 제작 시 수동 grep/파서 (검사 명령은 `/새인물` 스킬 §4 참조). CI 승격 후보 — 스크립트화하면 PR 게이트로 이동 가능.

### 2단 — 의미 검증 (전 콘텐츠 필수)

1단을 통과한 콘텐츠의 *내용* 을 전문 에이전트가 독립 검토:

- **신학**: lemuel-theology-reviewer — 정통 범위·영지주의/뉴에이지 유입·disputed_points 정직성·성경 인용 정확성(번역본 일치 포함)
- **정신건강**: lemuel-mental-health-safety — R1~R5 를 파일:라인 실측으로 검증, APPROVE / APPROVE-WITH-FIXES / BLOCK 판정
- 두 검토는 **병렬·독립** (서로의 결과를 보지 않음). 지적사항은 생성 담당(scenario-designer)에게 돌려 수정 후, 수정 결과를 **에이전트 보고가 아닌 직접 실측**으로 재확인.
- 런타임 등가물: CONTENT-WORKFLOW §3 AI 1차 검토 (생성 직후 auto-screening) — 같은 층, 다른 시점.

### 3단 — 합의 검증 (민감 콘텐츠만)

발동 조건 (하나라도 해당 시):

- R1 직접 취급 콘텐츠 (자살사고 본문 — 예: 왕상 19:4, 욥기 3장)
- Theme 11 (예수) — 기존 2-of-2 인간 검토 규칙 유지
- 신규 구원 카테고리 첫 도입 · disputed_points 에 심각도 높은 신학 분쟁 포함

방식:

- 서로 다른 렌즈의 독립 검토 3개(신학·안전·본문 정확성)를 병렬로 받고 **2/3 이상 동의**로 통과
- **R1 콘텐츠는 어떤 자동 합의로도 최종 승인 불가** — 인간 안전 검토자 사인오프가 마지막 게이트 (CONTENT-WORKFLOW §4~5 의 사람 검토와 접속)

## 2. 제약축 (R1~R5) 과의 관계

R1~R5 는 게이트가 아니라 **상수**다. 3단 어디를 통과했어도 R1~R5 위반이 발견되면 그 시점에 무조건 차단된다. 게이트는 제약축을 *검증하는 수단*이지, 제약축의 *예외 경로*가 아니다.
