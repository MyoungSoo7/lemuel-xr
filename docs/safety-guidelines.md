# lemuel-xr — Safety Guidelines

> *자문가 *필수 검증* 거버넌스를 폐기한 (2026-05-22) 후 *제작자가 자기 책임 으로* 지키는 안전 룰.*

자문이 *없다* 는 것이 *안전 룰이 없다* 는 뜻은 아니다. 자살예방 영역의 교육 콘텐츠는 본질적으로 *위기 상태의 사용자가 우연히 접속할 가능성이 0이 아닌* 영역이다. 본 문서는 그 가능성에 대해 *자문가에게 위임하지 않고 제작자가 자체적으로* 지키는 안전 룰을 정의한다.

## 1. 위기자원 상시 노출 (Crisis Resource Footer)

**모든 사용자 facing 화면** 에 다음 footer 를 영구 노출:

```
지금 위기 상태라면 — 1393 자살예방상담전화 (24시간, 무료)
```

- VR / AR / Web 어떤 플랫폼이든 *항상* 표시
- 사용자가 명시적으로 닫을 수 있어도 *세션 종료 시 자동 복원*
- 한국어 외 영어/일본어 등 추가 시 해당 언어권의 hotline 도 같이 표시 (예: 영어는 988)

**구현 위치:** Next.js `<RootLayout>` 의 fixed-position footer. 모바일·VR 모두 절대 가려지지 않게.

## 2. 트리거 표현 회피 (Trigger Warnings)

다음 표현은 *모든 콘텐츠* 에서 회피:

| 회피 표현 | 대안 |
|---|---|
| "자살하다 / 목숨을 끊다" | "삶을 놓다" 또는 *언급 자체 회피* |
| 자해 방법의 *구체적* 묘사 | 추상화 (예: "그는 길을 잃었다") |
| 절망의 *영광스러운 묘사* (자살을 미화) | 절망은 *극복의 대상* 으로만 묘사 |
| 종교적 *지옥·심판* 의 위협 | 사랑·용서·회복의 메시지 우선 |
| *현존하는 정치·종교 갈등* 의 직접 언급 | 시대 초월 메시지로 추상화 |

**적용 방법:** 모든 본문 (Scene 텍스트 / monologue / outcomes / AR practice 안내문) 에 적용. AI 사이드카 (Python FastAPI) 의 LLM 생성 텍스트는 사후 정규식 필터 + 매뉴얼 검토 *모두* 통과해야 release.

## 3. 사용자 정신건강 데이터 비수집 (No PHI Collection)

다음은 *수집·저장·전송 금지*:

- 사용자의 우울증/불안/PTSD/자살위험 *진단* 또는 *자가평가 점수*
- *PHQ-9 / GAD-7 / Columbia* 등 임상 검사 도구의 결과
- 사용자가 *자유 텍스트로 입력한* 정신건강 관련 자기보고
- *생체 데이터* (심박·EEG·시선추적 등) 중 정신건강 추론 가능한 형태

대신 수집 가능:
- 익명 *체험 만족도* (5점 척도)
- *습관 형성 기록* (AR 1~7 의 daily streak)
- *완료한 Scene* (요셉/모세/다윗/예수 미션의 진행 상태)

**구현:** DB 의 `emotion_classifications` 테이블에 사용자 자유 텍스트가 영구 저장되지 않게 *원본은 분류 직후 폐기*, 분류 결과 (예: `LONELY` enum) 만 보존.

## 4. AI 생성 텍스트 검증 (LLM Output Guardrails)

Python AI 사이드카 (Gemini / OpenAI / Anthropic) 가 생성한 모든 텍스트는 다음 4단 게이트 통과:

1. **System prompt 강제** — 모든 LLM 호출에 본 가이드라인 §2 (트리거 회피) 와 §1 (위기자원) 을 system prompt 로 prepend
2. **정규식 사후 필터** — 위 §2 의 회피 표현 패턴 매치 시 *블록* + Sentry 알림
3. **사용자 표시 직전 검증** — backend 가 LLM 응답을 frontend 로 보내기 직전 한 번 더 룰 적용
4. **랜덤 샘플링 매뉴얼 리뷰** — 매주 *생성된 텍스트의 5%* 를 제작자가 직접 읽고 가이드라인 위반 여부 점검

## 5. 출시 시 *추천 인용* (Endorsement, Not Validation)

자문가 *필수 검증* 은 폐기됐지만, 출시 시점의 *신뢰도 부스트* 를 위해 *추천 인용* 은 받는다:

- *신학교수 1명* — 본문의 신학적 정통성에 대한 *추천* (검증 아님, 추천)
- *정신건강 전문의 1명* — 콘텐츠가 *비위해 (do no harm)* 원칙을 지키는지에 대한 *추천*

이 추천 인용은:
- 출시 페이지 / 마케팅에 사용 가능
- *컨텐츠 결정* 에는 *바인딩 권한 없음* — 제작자가 최종 결정
- 추천 인용자의 이름·소속·코멘트는 동의 하에 공개

## 6. 사용자 의견 수렴 (Feedback, Not Approval)

사용자 피드백 채널을 운영하되, 그것을 *콘텐츠 변경의 의무* 로 만들지 않는다:

- 텔레그램 봇 / 이메일 / Google Form 등으로 피드백 수집
- 매주 정기 검토 — 가이드라인 위반·트리거 발견 시 *즉시* 콘텐츠 수정
- 단순 *취향 차이* 는 *반영 의무 없음*

## 7. 사고 발생 시 대응 (Incident Response)

만약 *위기 상태의 사용자가 콘텐츠로 인해 더 악화됐다는 신고* 가 들어오면:

1. **즉시** — 해당 콘텐츠 (Scene / monologue / practice) *임시 비활성화* (feature flag)
2. **24시간 안** — 제작자가 신고 내용 검토 + 원인 분석
3. **72시간 안** — 콘텐츠 *영구 수정* 또는 *영구 삭제* 결정 + 사용자에게 사후 안내
4. **사후** — 같은 패턴 재발 방지 룰을 본 문서에 *영구 추가*

## 8. 본 문서의 갱신 (Maintenance)

본 문서는 *살아있는 가이드라인* 이다. 다음 시점에 *반드시* 검토·갱신:

- 매 분기 (정기)
- 새 콘텐츠 도메인 (예: 새 인물 미션) 추가 시
- 사고 발생 후 (위 §7)
- 사용자 피드백에서 *반복적인 패턴* 이 발견될 때

갱신 이력은 git log 로 추적.

---

> *이 문서는 lemuel-xr 의 *안전 마지노선* 을 정의한다. 자문가가 없는 만큼 *각 룰의 위반은 즉시 사고 시그널* 로 해석한다. 의심스러우면 *콘텐츠를 빼는 쪽* 으로 결정한다.*
