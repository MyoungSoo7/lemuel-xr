# lemuel-xr — Safety Guidelines

> *자문가 *필수 검증* 거버넌스를 폐기한 (2026-05-22) 후 *제작자가 자기 책임 으로* 지키는 안전 룰.*

자문이 _없다_ 는 것이 _안전 룰이 없다_ 는 뜻은 아니다. 자살예방 영역의 교육 콘텐츠는 본질적으로 _위기 상태의 사용자가 우연히 접속할 가능성이 0이 아닌_ 영역이다. 본 문서는 그 가능성에 대해 _자문가에게 위임하지 않고 제작자가 자체적으로_ 지키는 안전 룰을 정의한다.

## 1. 위기자원 상시 노출 (Crisis Resource Footer)

**모든 사용자 facing 화면** 에 다음 footer 를 영구 노출:

```
지금 위기 상태라면 — 109 자살예방 상담전화 (24시간, 무료)
```

> **번호 정본 (2026-08-02 교정)** — 2024-01-01 부로 분산돼 있던 자살예방 상담전화가 **109** 로 통합됐다
> ([보건복지부](https://www.mohw.go.kr/board.es?act=view&bid=0027&cg_code=&list_no=1479607&mid=a10503000000&tag=)).
> 통합 대상은 _자살예방 상담 기능_ 뿐이다 — 정신건강상담전화(1577-0199)·청소년전화(1388)·여성긴급전화(1366) 등은
> 종전과 같이 담당 분야 상담을 계속한다 ([보건복지상담센터 FAQ](https://www.129.go.kr/109)).
> 구 번호 1393 이 _불통_ 이라는 근거는 없다 — 정번호 지위만 잃었다.
>
> **문서에 번호를 새로 적지 말 것.** 런타임 카피는 `{{crisis_resources.default}}` 토큰만 쓰고,
> 실제 번호는 `crisis_resources` 카탈로그(DB) 한 곳에서 주입된다. 시나리오 yml 하드코딩은
> `ScenarioHotlineRatchetTest` 가 막는다.

- VR / AR / Web 어떤 플랫폼이든 _항상_ 표시
- 사용자가 명시적으로 닫을 수 있어도 _세션 종료 시 자동 복원_
- 한국어 외 영어/일본어 등 추가 시 해당 언어권의 hotline 도 같이 표시 (예: 영어는 988)

**구현 위치:** Next.js `<RootLayout>` 의 fixed-position footer. 모바일·VR 모두 절대 가려지지 않게.

## 2. 트리거 표현 회피 (Trigger Warnings)

다음 표현은 _모든 콘텐츠_ 에서 회피:

| 회피 표현                              | 대안                              |
| -------------------------------------- | --------------------------------- |
| "자살하다 / 목숨을 끊다"               | "삶을 놓다" 또는 _언급 자체 회피_ |
| 자해 방법의 _구체적_ 묘사              | 추상화 (예: "그는 길을 잃었다")   |
| 절망의 _영광스러운 묘사_ (자살을 미화) | 절망은 _극복의 대상_ 으로만 묘사  |
| 종교적 _지옥·심판_ 의 위협             | 사랑·용서·회복의 메시지 우선      |
| _현존하는 정치·종교 갈등_ 의 직접 언급 | 시대 초월 메시지로 추상화         |

**적용 방법:** 모든 본문 (Scene 텍스트 / monologue / outcomes / AR practice 안내문) 에 적용. AI 사이드카 (Python FastAPI) 의 LLM 생성 텍스트는 사후 정규식 필터 + 매뉴얼 검토 _모두_ 통과해야 release.

## 3. 사용자 정신건강 데이터 비수집 (No PHI Collection)

다음은 _수집·저장·전송 금지_:

- 사용자의 우울증/불안/PTSD/자살위험 _진단_ 또는 _자가평가 점수_
- _PHQ-9 / GAD-7 / Columbia_ 등 임상 검사 도구의 결과
- 사용자가 _자유 텍스트로 입력한_ 정신건강 관련 자기보고
- _생체 데이터_ (심박·EEG·시선추적 등) 중 정신건강 추론 가능한 형태

대신 수집 가능:

- 익명 _체험 만족도_ (5점 척도)
- _습관 형성 기록_ (AR 1~7 의 daily streak)
- _완료한 Scene_ (요셉/모세/다윗/예수 미션의 진행 상태)

**구현:** DB 의 `emotion_classifications` 테이블에 사용자 자유 텍스트가 영구 저장되지 않게 _원본은 분류 직후 폐기_, 분류 결과 (예: `LONELY` enum) 만 보존.

## 4. AI 생성 텍스트 검증 (LLM Output Guardrails)

Python AI 사이드카 (Gemini / OpenAI / Anthropic) 가 생성한 모든 텍스트는 다음 4단 게이트 통과:

1. **System prompt 강제** — 모든 LLM 호출에 본 가이드라인 §2 (트리거 회피) 와 §1 (위기자원) 을 system prompt 로 prepend
2. **정규식 사후 필터** — 위 §2 의 회피 표현 패턴 매치 시 _블록_ + Sentry 알림
3. **사용자 표시 직전 검증** — backend 가 LLM 응답을 frontend 로 보내기 직전 한 번 더 룰 적용
4. **랜덤 샘플링 매뉴얼 리뷰** — 매주 _생성된 텍스트의 5%_ 를 제작자가 직접 읽고 가이드라인 위반 여부 점검

## 5. 출시 시 _추천 인용_ (Endorsement, Not Validation)

자문가 _필수 검증_ 은 폐기됐지만, 출시 시점의 _신뢰도 부스트_ 를 위해 _추천 인용_ 은 받는다:

- _신학교수 1명_ — 본문의 신학적 정통성에 대한 _추천_ (검증 아님, 추천)
- _정신건강 전문의 1명_ — 콘텐츠가 _비위해 (do no harm)_ 원칙을 지키는지에 대한 _추천_

이 추천 인용은:

- 출시 페이지 / 마케팅에 사용 가능
- _컨텐츠 결정_ 에는 _바인딩 권한 없음_ — 제작자가 최종 결정
- 추천 인용자의 이름·소속·코멘트는 동의 하에 공개

## 6. 사용자 의견 수렴 (Feedback, Not Approval)

사용자 피드백 채널을 운영하되, 그것을 _콘텐츠 변경의 의무_ 로 만들지 않는다:

- 텔레그램 봇 / 이메일 / Google Form 등으로 피드백 수집
- 매주 정기 검토 — 가이드라인 위반·트리거 발견 시 _즉시_ 콘텐츠 수정
- 단순 _취향 차이_ 는 _반영 의무 없음_

## 7. 사고 발생 시 대응 (Incident Response)

만약 _위기 상태의 사용자가 콘텐츠로 인해 더 악화됐다는 신고_ 가 들어오면:

1. **즉시** — 해당 콘텐츠 (Scene / monologue / practice) _임시 비활성화_ (feature flag)
2. **24시간 안** — 제작자가 신고 내용 검토 + 원인 분석
3. **72시간 안** — 콘텐츠 _영구 수정_ 또는 _영구 삭제_ 결정 + 사용자에게 사후 안내
4. **사후** — 같은 패턴 재발 방지 룰을 본 문서에 _영구 추가_

## 8. 본 문서의 갱신 (Maintenance)

본 문서는 _살아있는 가이드라인_ 이다. 다음 시점에 _반드시_ 검토·갱신:

- 매 분기 (정기)
- 새 콘텐츠 도메인 (예: 새 인물 미션) 추가 시
- 사고 발생 후 (위 §7)
- 사용자 피드백에서 _반복적인 패턴_ 이 발견될 때

갱신 이력은 git log 로 추적.

---

> *이 문서는 lemuel-xr 의 *안전 마지노선* 을 정의한다. 자문가가 없는 만큼 *각 룰의 위반은 즉시 사고 시그널* 로 해석한다. 의심스러우면 *콘텐츠를 빼는 쪽* 으로 결정한다.*
