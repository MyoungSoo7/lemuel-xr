# MVP-RUTH — XR 실 콘텐츠 (Scene 별 대본·인터랙션·자원)

> ⚠️ **인간 사인오프 대기** — 이 문서는 설계(`docs/MVP-RUTH.md`)와 저작(`content/ruth/*.yml`)을
> 런타임 산출물(`backend/src/main/resources/scenarios/ruth.yml`)로 옮기는 **런타임 대본**이다.
> `docs/CONTENT-WORKFLOW.md` 의 신학·정신건강 검토자 2인 사인오프는 **아직 없다.**
> 이 문서 어디에도 "검토를 통과했다" 는 진술이 없다.
>
> **런타임 노출은 아직 닫혀 있다** — `Character` enum 에 `RUTH` 가 없고,
> `ScenarioYamlLoader.loadAll()` 은 `Character.entries` 만 순회한다(`ScenarioYamlLoader.kt:28`).
> 그래서 `scenarios/ruth.yml` 은 존재하되 **로드되지 않는다.** enum 추가가 곧 노출이며,
> 그 한 줄이 사인오프 게이트다.

**이 문서가 하지 않은 것 (먼저 밝힌다)**

1. **성구 자구를 새로 쓰지 않았다.** 모든 자막은 `docs/VERSES-RUTH-GAE.md`(개역개정 실측)에서
   `content/ruth/*.yml` 로 이미 옮겨진 LOCKED 정본을 **문자 그대로** 재사용했다. 이 문서에서
   자구를 다듬은 곳은 0곳이다.
2. **동의 카드·면책 문안·마감 세 줄을 새로 쓰지 않았다.** 정본은 `docs/RUTH-LOCKED-STRINGS.md`
   이고 `scripts/check_ruth_captions.py` 가 그 파일을 읽어 대조한다. 여기서 고치면 그 검사가
   빨개진다 — 그것이 의도된 동작이다.
3. **묵상 제안 9종(§5-2 캐시 키)을 저작하지 않았다.** 이유는 §6-3 에 적었다. 요약하면,
   그것은 이 미션에서 **유일하게 LLM 이 담당하는 층**이고 기본값이 `off` 이며, 미리 문자열로
   박아 두면 "opt-in 이라 안 나간다" 는 계약과 "이미 써 두었다" 는 사실이 어긋나기 때문이다.
4. **자동 진행 타임라인(`at_sec`)을 쓰지 않았다.** 솔로몬·다윗 대본의 `script[].at_sec` 형식을
   그대로 베끼면 `content/ruth/*.yml` 의 `caption_pacing.auto_advance: false` 와 정면으로
   충돌한다. 자세한 것은 §0.3.

## 0. 공통 XR 컨벤션 (5 Scene 전체 적용)

### 0.1 진입·동의 게이트 — 카드 3장 2단

| 카드                        | 정의 위치 | 덮는 Scene | 거절 시 착지                    |
| --------------------------- | --------- | ---------- | ------------------------------- |
| `ruth_entry_consent`        | Scene 1   | 1, 2       | Scene 3 (+ 브리지 나레이션 1줄) |
| `ruth_midpoint_consent`     | Scene 3   | 3, 5       | `closing` 센티널 → 종결 화면    |
| `ruth_scene4_night_warning` | Scene 4   | 4          | Scene 5                         |

- 문안 3종은 `docs/RUTH-LOCKED-STRINGS.md` 의 `consent_cards` 블록이 정본이다.
- 카드 3 은 `default_focus: none` — [계속한다]에도 [건너뛰기]에도 기본 포커스를 주지 않는다.
  기본 포커스는 그 자체가 권유다(다니엘 `scene4.yml:28` 선례).
- **스킵 목적지는 `consent_card_id` → `skip_alternative_scene_id` → (문자열이면)
  `conditional_blocks[].id` 의 쌍으로 계약한다.** Scene 5 만 문자열이며 값은
  `ruth_scene5_alt_short` 다. 정수 자기참조(`skip_alternative_scene_id: 5`)를 쓰면 타입 검사는
  통과하면서 축약 블록을 지목하지 못해 **도달 불가**가 된다 — 검사는 초록, 사용자는 전문을 본다.

| ----- | ------------- | ------------------- | ------------------------------------ |

`interaction` 값 5종은 전부 하우스에 이미 있는 값이다(`scenarios/*.yml` 실측:

`contemplative` 2 · `grab_and_place` 1). 룻이 새 값을 도입하지 않는다.

### 0.3 시간·공간 안락성 — **자동 진행 타임라인을 쓰지 않는다**

솔로몬·다윗·모세 대본은 `extras.script[]` 아래에 `at_sec` 타임라인을 둔다. 룻은 두지 않는다.

`content/ruth/scene1~5.yml` 은 전부 다음을 선언한다.

```yaml
caption_pacing:
  auto_advance: false
  rewind_allowed: true
```

`at_sec` 타임라인은 정의상 **시간이 자막을 넘기는 구조**다. 두 선언을 한 파일에 같이 두면
런타임 구현자가 어느 쪽을 따를지 알 수 없고, 십중팔구 타임라인이 이긴다 — 그쪽이 코드로
표현하기 쉽기 때문이다. 그러면 사별 사용자가 나오미의 탄식 자막을 **읽는 속도와 무관하게**
넘기게 된다. 그래서 `ruth.yml` 은 `captions[]` 를 순서 배열로만 싣고 `advance: user` 를 명시한다.

`duration_seconds_target` 은 **에셋·오디오 길이 산정용 목표치**이지 스케줄이 아니다.
(Scene 1 80 · 2 90 · 3 110 · 4 60 · 5 90 = 합 430초 ≈ 7분 상한. 하한 5분은 사용자가 빠르게
넘길 때의 값이다.)

- 시야 차단·촉각 피드백·생체 연동 **전 Scene 금지**(헌장 §2.1-b 5항 · `biometrics_used: false`).
- 카메라는 전 Scene 고정 리그다. 사용자 시점을 눕히거나 올려다보게 두지 않는다(2항).
- 인물은 전신·원경만. 얼굴 클로즈업 0건(4항).

### 0.4 결정 기록 (백엔드)

기록되는 결정은 **1개뿐**이다.

| `decision_key`    | 발행 Scene | 값                                   | 소비처             |
| ----------------- | ---------- | ------------------------------------ | ------------------ |
| `belonging_label` | 2          | `stay_beside` / `step_back` / `null` | Scene 5 마감 한 줄 |

- 미선택은 실패가 아니라 `null` 이다. 타이머가 없으므로 **만료도 없다.**
- 이 값은 서사·자막·에셋을 갈라놓지 않는다. 갈리는 것은 마감 한 줄뿐이다.
- 이삭 줍기(Scene 3)는 **아무것도 기록하지 않는다.** 수확량 필드 자체가 없다.

### 0.5 항상 노출되는 층 — 면책 4줄 · 위기 리마인더 · 나가기

면책 4줄(`suffering_disclaimer`)과 위기 리마인더는 **서로 다른 6개 블록**에 붙는다.
Scene 5 를 두 번 세지 않는다 — 같은 파일이지만 다른 블록이고, 계수 기준은 파일이 아니라
**블록 경로**다.

| #   | 블록 경로                                   |
| --- | ------------------------------------------- |
| 1~5 | `scene{1..5}` → `environment.ui_overlays`   |
| 6   | `scene5` → **`closing_screen.ui_overlays`** |

6번의 부모가 `environment` 가 **아닌** 이유: `closing_only` 진입에서 `environment` 는
렌더되지 않는다. 안전층을 그 아래 두면 **렌더 안 되는 블록에 안전장치를 매다는 조용한 실패**가 된다.

「잠시 멈추기 · 나가기」 버튼은 5 Scene 상시 노출이며 메뉴에 숨기지 않는다(§4-5).
**어느 지점에서 나가도 종결 화면에 착지한다** — 거절 경로와 완주 경로의 산출물이 같다.

위기 연락처는 **하드코딩 금지**, `{{crisis_resources.default}}` 토큰만 쓴다.
`ScenePayloadAssembler` → `CrisisTokenResolver` 가 정본으로 치환하며
`ScenarioHotlineRatchetTest` 가 이를 강제한다. 번호를 yml 에 직접 적으면 정책 개정 때
낡은 번호가 위기 카피에 그대로 남는다.

### 0.6 미션 전체 톤 정책 (R2/R3 사전 가드)

금지 토큰 **22종**(`docs/MVP-RUTH.md` §15)은 이미 전역 목록
(`application.yml` `safety.forbidden-tokens.list`, 현재 680종)에 반영돼 있다 —
2026-08-11 실측 미반영 0건. `ruth.yml` 은 같은 22종을 Scene 별 게이트로 다시 선언한다.
**저작(`content/`)과 런타임(`scenarios/`)은 자동 동기화되지 않으므로**, 런타임 파일이
스스로 선언하지 않으면 이 파일에 대해서는 아무것도 집행되지 않는다
(`ContentSafetyGateEnforcementTest` 가 잡는 그 형태다).

아래 표의 각 행은 **금지 토큰을 인용하는 줄**이므로 규약대로 선언 마커를 단다
(`lint_forbidden_tokens` · G6d). 계열 1 은 배제 자구와 같은 문자열이라
`EXCLUSION-DECL` 도 함께 단다(G9d). 마커가 없으면 게이트는 이 표를 *위반*으로 읽는다.

| 계열 | 축                 | 예시 토큰                                             | 선언                                                       |
| ---- | ------------------ | ----------------------------------------------------- | ---------------------------------------------------------- |
| 1    | 동반사망 관념      | `나도 죽어` · `따라 죽` · `같이 묻히`                 | `lint_forbidden_tokens` <!-- EXCLUSION-DECL --> · 배제 E1' |
| 2    | 고난의 신적 귀속   | `연단하시려고` · `다 뜻이 있어`                       | `lint_forbidden_tokens`                                    |
| 3    | 회복 압박          | `이제 그만 일어나` · `감사하면 회복` · `빨리 잊고`    | `lint_forbidden_tokens`                                    |
| 4    | 공로·보상 프레이밍 | `결국 보상받았` · `참으니 복이` · `그만큼 헌신했으니` | `lint_forbidden_tokens`                                    |
| 5    | 마감 줄 평가 어휘  | `곁을 지켰` · `물러섰지만` · `그래도 잘` · `덕분에`   | `lint_forbidden_tokens`                                    |

계열 5 가 존재하는 이유는 마감 세 줄 때문이다. **사용자의 선택을 되읽어 평가하는 어휘가
한 개라도 들어오면** 애도의 거리가 채점표가 된다.

## 2. Scene 2 — 「빈 손의 귀향」 (90초 · 등급 B) ★ 인터랙션 ①

### 2.1 배경·환경

- 베들레헴 성읍 어귀. 보리 추수가 막 시작된 때. 높은 해, 짧은 그림자.
- 카메라: `fixed_wide_outside_gate`. 군중은 **원거리 실루엣**이며 웅성임도 원거리 정위만.
- 나오미는 룻의 곁에 둔다. 군중 속 구경거리로 세우지 않는다(SR-4 1항).

### 2.2 대본 (자막 3장 · 탄식층)

| 순서 | 화자 표기   | 절         | 자막                                                                                     |
| ---- | ----------- | ---------- | ---------------------------------------------------------------------------------------- |
| 1    | 성읍 사람들 | 룻 1:19 중 | 이이가 나오미냐                                                                          |
| 2    | 나오미      | 룻 1:20 중 | 나를 나오미라 부르지 말고 나를 마라라 부르라 이는 전능자가 나를 심히 괴롭게 하셨음이니라 |
| 3    | 나오미      | 룻 1:21 중 | 내가 풍족하게 나갔더니 여호와께서 내게 비어 돌아오게 하셨느니라                          |

**SR-8 귀속 표기 — 이 Scene 의 핵심 안전 장치다.** 나오미의 두 자막 위에 화자 이름을
**상시** 표기한다(페이드 없음). 1인칭 XR 에서 표기가 없으면 이 문장이 **사용자 자신의
문장**으로 읽힌다. "전능자가 나를 심히 괴롭게 하셨다" 를 사용자 1인칭으로 읽히게 두는 것과
나오미의 탄식으로 읽히게 두는 것은 완전히 다른 매체 행위다.

**비승격·비반박.** 미션 화자는 나오미의 말을 교리로 승격하지도, 교정하지도 않는다.
서사 내 반박·위로 대사가 0개인 것은 누락이 아니라 설계다. 비서사 안전층(면책 오버레이·
위기 리마인더)은 예외이며 필수다.

**룻 1:21 후반은 없다** — `여호와께서 나를 징벌하셨고`(E3) <!-- EXCLUSION-DECL --> 는 탄식과 달리 고통을 **벌로
설명한다.** 앞 절은 탄식이고 뒷 절은 귀속이다. 자른 지점이 정확히 그 경계다.

### 2.3 인터랙션 ① — 애도의 거리

바닥에 두 지점이 표시된다. 사용자는 그중 하나로 이동하거나, 아무 데도 가지 않는다.

| 값            | 표시             | 성격                                          |
| ------------- | ---------------- | --------------------------------------------- |
| `stay_beside` | 곁에 남는다      | 정답 아님                                     |
| `step_back`   | 한 걸음 물러선다 | 정답 아님                                     |

## 6. 백엔드·LLM 계약

### 6-1. LLM 호출 지점

| 분기 지점       | 출력 종수 | 생성 방식                               |
| --------------- | --------- | --------------------------------------- |
| Scene 2 라벨    | 2 (+null) | **선택만. 생성 없음**                   |
| Scene 5 마감 줄 | **3**     | 사전 작성 문자열. LLM 없음              |
| 저널 문장       | 2         | 사전 작성. LLM 없음                     |
| 묵상 (opt-in)   | 가변      | LLM. `llm_optin_only: true`, 기본 `off` |

→ **LLM 호출 0회로 미션이 완주되며, 그것이 기본 경로다.**
캐시 대상이 3종 유한 집합이라 **사전 큐레이션이 곧 캐시**다. 9-패턴 사전 캐싱 전략이
필요 없는 구조이며, 그것이 이 미션이 택한 안전 설계다.

### 6-2. `faith_tone` 적용 범위

| 대상               | 적용                    |
| ------------------ | ----------------------- |
| 성경 자막 정본     | ❌                      |
| SR-1 종결 자막     | ❌                      |
| 면책 문안 4줄      | ❌                      |
| 동의 카드 3종      | ❌                      |
| 마감 세 줄         | ❌ (SR-9)               |
| 묵상 제안 (opt-in) | ✅ **유일한 적용 대상** |

### 6-3. 묵상 제안 9종을 이 문서에서 저작하지 않은 이유

`docs/MVP-RUTH.md` §5-2 는 `ruth_meditation_{belonging_label}_{faith_tone}` 9종의
캐시 키를 정의한다. 솔로몬 대본(§6)이 재정향 문구 9종을 문자열로 저작한 것과 대비된다.
룻에서는 저작하지 않았고, 이유는 셋이다.

1. **기본값이 `off` 다.** 미리 문자열로 박아 두면 "opt-in 이라 안 나간다" 는 계약과
   "이미 써 두었다" 는 사실이 어긋나고, 다음 사람이 `default: on` 으로 바꾸는 문턱이
   문자열 저작 비용만큼 낮아진다.
2. **R1 latch 이후에는 제시되지 않는다**(`suppressed_after_r1_latch: true`).
   위기 감지 후 억제되는 층을 본편과 같은 확정도로 저작하면, 억제가 예외처럼 보인다.
3. **이 미션에서 유일하게 LLM 이 담당하는 층이다.** 여기까지 정적으로 채우면
   "LLM 호출 0회" 는 사실이 되지만 `llm_optin_only` 는 죽은 키가 된다.

⚠️ 그러므로 **묵상 경로는 현재 미저작 상태이며, 이 문서는 그것을 완료로 세지 않는다.**
9종이 실제로 필요해지는 시점은 opt-in UI 가 붙는 시점이고, 그때 별건으로 저작하고
신학 검토를 받는다.

### 7-1. R1 우선순위 (Scene 5)

```
1. R1 위기 카드
2. 종결 자막 도달 보장
3. 서사 진행
```

⚠️ 2번과 latch 규정의 관계에 주의 — latch 발동 시 **종결 자막도 렌더되지 않는다.**
2번은 "위기가 없는 경로에서 종결 자막 도달을 보장한다" 는 뜻이지 latch 를 뚫는다는 뜻이 아니다.
이 두 줄은 `content/ruth/scene5.yml` 에 각각 `priority_order` 와 `latch_note` 로 나뉘어 있고,
**한쪽만 읽으면 반대로 구현된다.**

### 7-2. 감정 분류기 사별 어휘 — 해소됨, 단 탐지 한계가 남는다

**정정(2026-08-11).** 이 절은 처음에 "`docs/EMOTION-CLASSIFIER.md` 3단 사전에 사별 특이형
동반사망 표현이 없고, `release_blockers` 에 `resolved: false` 로 등재된 출시 차단 항목"이라고
적었다. **틀렸다.** 실측하면 `scripts/gates/ruth.yml:290-308` 의 해당 blocker 는
`resolved: true` · `resolved_at: "2026-08-06"` 이고, `docs/EMOTION-CLASSIFIER.md` 에는
사별 표현이 등재돼 있다. 출시 차단 항목이 아니다.

남는 것은 차단이 아니라 **탐지 한계**다. 같은 blocker 의 `caveat` 이 기록하듯 「마지막으로
정리」 같은 완곡·정황 의존 표현은 여전히 사전에 걸리지 않는다. 이것은 재현율을 정밀도와
맞바꾼 **의도된 선택**으로 기록돼 있다 — 사전 기반 분류기에서 이 표현군을 잡으려면
정상 발화 대량 오탐을 감수해야 하기 때문이다.

이 대본이 그 한계를 좁히지 않는다. 다만 R1 리스너가 5개 Scene 상시라는 것과
사전 재현율은 다른 층이므로, 완곡 표현이 사전에서 새더라도 위기 카드 경로 자체가
닫히는 것은 아니다.
